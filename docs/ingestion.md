## Rebuild outputs

```bash
uv run --locked python scripts/build_corpus.py
```

The builder writes `reports/core_rules.txt` and `reports/index_blocks.jsonl`; use `--output-dir PATH` to change the destination. It verifies source PDF/snapshot hashes, exports uncorrected pages, applies all 36 pages of verified corrections in a temporary directory, and removes intermediate Markdown, HTML, PNG, and audit JSON. Historical previews and migration reports are not dependencies.

The separate `reports/parent_child_blocks.jsonl` is generated by `scripts/embed_parent_child.py`, not by this builder. Keep original inputs in `data/` and corrections in `config/corrections/core_rules/`; do not index those as duplicate documents.

## Content and provenance

All 60 PDF pages are checked as source inputs. `config/index_policy.json` excludes pages 1, 2, 3, 4, 31, and 40, initially yielding 263 heading blocks across 54 pages. Noise cleanup and explicit relationships leave 228 baseline rule blocks. Historical 26-unit test exports were removed. TXT and JSONL contain the same rule text; TXT is a reading copy.

Corrected pages are regenerated; other pages come from `data/core_rules.docling.json` and remain `unreviewed`. Blocks mixing reviewed and unreviewed pages are `partially_reviewed`. `reviewed_correction` only means specified corrections were verified, not that every figure was fully converted into text. Page-specific handlers remain necessary for layouts, tables, figures, and stratagem cards.

Baseline boundaries follow Markdown headings. `text` retains heading/body; `embedding_text` includes existing ancestor headings where applicable. Tables, stratagems, and captions are not split by length or blank lines. Heading context is initially page-local; `config/corpus_relations.json` explicitly joins approved cross-page rules, tables, and captions.

Image links become original PDF page references. Captions are preserved without inferring spatial relationships. `assets` records captions, physical PDF pages, regenerated image hashes, and `stored: false`, without paths to deleted PNG files. OCR is disabled.

Each JSONL record includes:

- `block_id`, `document_id`, `section_title`, `section_path`, and `content_type`.
- PDF/snapshot paths and hashes, correction manifest hash, index policy and relationship configuration paths/hashes.
- `page_number` and `page_numbers`: 1-based physical PDF pages.
- `review_status`, `origin`, and `warnings`.
- `txt_span`: the Unicode `[start, end)` range of `embedding_text` in TXT; `txt_sha256` verifies the full TXT.
- `source_segments`: source block IDs, pages, page Markdown hashes, `markdown_span`, source fragment hashes, correction/audit hashes, original review status, and final block-relative `text_span` and rendered-text hashes. Do not confuse original Markdown ranges with final text ranges.
- `source_block_ids` and executed `associations`.
- `corpus_audit` in the first record: excluded ranges and reasons for auditing, not embedding.

Initial IDs derive from the PDF, page, range, and content. Optimized IDs derive from retained fragments, text, and relationship hashes. Schema version 3 replaces obsolete single-page block-level Markdown/correction fields with per-fragment `source_segments` to avoid incorrect provenance on merged blocks.

## Noise and explicit relationships

`config/corpus_relations.json` pins PDF/Docling hashes and each operation's source IDs, titles, pages, and text hashes. Remove only configured standalone page/navigation lines; do not index image-only blocks or headings without content. Preserve meaningful numerical text, tables, captions, and inherited heading context.

Approved associations include D3 on page 9, Wound Roll on pages 21–22, Select Weapon on pages 33–34, Make Attacks on pages 34–35, and the aircraft movement caption on page 54 associated with the movement rule on page 53. Adjacent headings/continuations are not merged automatically. Changed sources stop the build until configuration is reviewed.

Each fragment retains its original review status. `source_pdf_page` refers to the actual asset source page, which can differ from the rule's first `page_number`.

## Examples and terrain

`config/rule_context.json` verifies Unit Coherency example relationships and six terrain scopes on pages 45–48 using original source IDs and hashes; the baseline remains 228 blocks.

Examples' `parent_rule_id` and the main rule's `example_block_ids` establish relationships. Queries retain original vector rankings and supplement missing complete main rules through `related_evidence`; supplementary evidence is not given an artificial vector rank. Incomplete indexes missing main rules fail explicitly.

Terrain context includes `terrain` and `rule`, repairing Woods/Ruins heading paths. `embedding_text` gains explicit names while original body text/hashes and source segments stay unchanged. `context_provenance` identifies the heading sources separately. Identical rule wording for distinct terrain types remains separate.

Configuration/hash mismatches stop rebuilding. Updated context changes TXT spans/hashes and requires matching rebuilt embeddings.

## Parent-child chunks

Read only `reports/index_blocks.jsonl`, using `embedding_text` and inherited provenance. `scripts/embed_parent_child.py` writes parents and children to the separate JSONL. Child records have exact parent-relative character spans, parent hashes, and involved pages. Keep original source-segment granularity for Markdown provenance. Do not reduce cross-page citations to one page or index TXT alongside JSONL. See README for token thresholds and vector reuse rules.

## Parse a new snapshot

```bash
uv run --locked python scripts/parse_pdf.py "data/Core Rules.pdf"
```

This creates `data/core_rules.docling.json`. First use may download models. Re-parsing can change hashes; existing corrections reject incompatible inputs and must be reviewed before reuse.

## Vector storage

`reports/index_blocks.jsonl` is the baseline corpus input. Chroma defaults are in `config/embeddings.json`. Import a matching NPZ with `scripts/embed_rules.py --provider qwen --import-npz` without re-encoding documents. Runtime Chroma files live in `storage/chroma/`; NPZ backups remain in `storage/embeddings/`, both excluded from Git.

Collections are versioned by provider, configuration fingerprint, and corpus hash. Records retain precomputed vectors, embedding text, scalar terrain/review filter fields, and lossless source JSON. Queries always use the project provider rather than a database-selected embedding function.

Cosine distance is exposed as `1 - distance`. Use `--backend npz` for the exact baseline or default Chroma for database search and the same retrieval checks. Changed content/model settings require a matching import or rebuild; never silently append incompatible vector spaces to an existing collection.
